# 电信行业经营决策 Agent｜业务场景速读

> 阅读对象：不了解运营商业务、需要在 CogSeed 中复现本案例的产品、开发或测试同事  
> 阅读时间：约 8—10 分钟  
> 使用边界：本文解释脱敏演示案例的业务逻辑，不代表任何真实省份、组织或员工的经营事实。

## 第1页｜先看懂业务：这个Agent究竟在帮助谁做什么决定

### 1. 场景不是“查人数”，而是判断人是否用在正确的业务上

电信一线经营中，管理者经常会问：“当前人员配置是否合理，要不要增人或调人？”

如果只比较人数、业务量或平均积分，很容易得出错误结论。真正需要判断的是四件事：

1. **总量是否够用**：现有人力能否覆盖安装、维护、营销和必要的保障任务；
2. **结构是否合理**：装维与营销等岗位比例是否匹配当前业务；
3. **人岗任务是否匹配**：高价值任务是否交给有对应产品经验、能力、触点和同类实绩的人；
4. **结果是否兑现**：业务量最终有没有转化为一次竣工、有效订单、质量和客户保有。

因此，这个Agent不是“自动排班工具”，也不是“按积分给员工排名”。它首先帮助网格负责人把问题判断清楚，再形成有证据、可复核、待确认的经营建议。

### 2. 四级组织怎么理解

本演示统一采用：

```text
省公司 → 地市公司 → 区县公司 → 网格
```

| 层级 | 在本场景中的作用 |
|---|---|
| 省公司 | 看跨区域共性问题、经营规则和资源方向 |
| 地市公司 | 看区县差异，协调专业能力和资源 |
| 区县公司 | 负责跨网格协调、支援与管理确认 |
| 网格 | 最小经营单元，直接承接客户、任务和经营结果 |

本案例从**网格负责人**视角出发。只有当网格内部确实无法覆盖业务时，才进入跨网格支援或增员评估。不能一看到结果低，就直接得出“缺人”。

### 3. 两类一线角色

- **装维人员**：负责宽带、家庭组网、家庭安防等业务的安装、调测、维护、修障和现场交付。关注一次竣工、返工、准时完成、质量与当前负荷。
- **营销人员**：负责识别、触达和转化客户机会。关注客户意向、产品经验、触点、有效订单以及后续保有。

两类岗位共同服务家庭业务，但工作性质不同，因此积分含义也不同：装维使用**履约积分**，营销使用**贡献积分**。两类原始积分不能直接横向比较。

### 4. 页面上的五个指标怎么看

指标以同类口径基准100%为参照：

| 指标 | 本期值 | 业务含义 |
|---|---:|---|
| 装维业务量指数 | 88% | 装维任务量不算高，但也不是没有任务 |
| 装维结果指数 | 31% | 任务结果明显没有随业务量兑现 |
| 营销业务量指数 | 102% | 营销机会量已经达到或略高于基准 |
| 营销结果指数 | 49% | 有机会，但有效转化偏低 |
| 质量指数 | 61% | 交付与结果质量仍有明显改善空间 |

核心阅读方式不是看某一个数字，而是看“**业务量不低，结果却明显偏低**”的组合。这通常提示管理者继续检查任务分配、能力匹配和执行质量，而不是立刻增员。

## 第2页｜再看懂案例：为什么结论是“先不增员，内部重排”

### 1. 案例基本盘

- 分析对象：某省／某市／某区县／家庭业务A网格；
- 当前人员：10人，其中装维7人、营销3人；
- 当前问题：业务量存在，但装维结果、营销结果和质量都没有同步兑现；
- 容量核验：现有7名装维能够覆盖本期6项复杂任务，且故障、巡检和应急保障预留不受影响；3名营销能够覆盖当前机会池。

因此，现有证据暂不支持“人员总量不足”。

### 2. 真正命中的那根针

本案例的核心根因是：

> 高价值任务和机会没有同时按产品价值、人员能力、客户触点与同类实绩进行匹配。

它分别体现在两条业务链上：

**装维链：复杂任务没有进入最匹配的承接队列**

- 共有6项复杂家庭网络履约任务；
- 其中4项没有优先进入技能和当前负荷都匹配的人员队列；
- 结果是延期、返工和一次竣工风险上升；
- 该问题对应约52个指数点的影响。

**营销链：高意向机会没有优先交给同类实绩更稳的人**

- 共有18条高意向家庭客户机会；
- 只有5条分配给同产品、同客群转化更稳的营销A；
- 营销C承接7条，但仅1条形成有效订单；
- 该问题对应约45个指数点的影响。

这里的“根因”必须同时包含对象、数量、匹配条件和结果影响，不能只写“人员能力不足”“协同有待提升”等泛化文字。

### 3. Agent应形成什么经营决定

**配置判断**：本期保持10人及7名装维、3名营销的岗位结构，先在网格内部重排任务与机会，暂不申请跨网格支援。

**装维动作**：

- 装维A主承接复杂家庭网络工单；
- 装维A带装维B完成2项真实任务；
- 复核一次竣工、返工和准时完成情况；
- 其他装维分别保持、保障预留、质量复盘、负荷控制或专项战训。

**营销动作**：

- 营销A优先承接高意向家庭客户；
- 营销A带营销B、营销C复盘同产品、同客群话术；
- 复核有效订单和早期保有；
- 不是简单把所有机会都交给最高分人员，而是通过主承接和真实任务带教改善整体能力。

### 4. 积分为什么可信，又为什么不能只看积分

积分必须能够回到具体事件。例如：

- 装维A履约积分94.34＝复杂家庭网络标准包竣工90.00＋主设备激活调测4.34；
- 营销A贡献积分368＝家庭宽带有效订单117＋家庭组网有效订单94＋家庭安防有效订单74＋移动产品贡献83。

积分在本案例中用于解释同岗位人员的能力和结果，但不能替代产品经验、客户触点、当前负荷和质量结果。只有平均积分、没有个人事件明细时，Agent必须停止点名，返回“证据不足”。

### 5. 建议必须能够回看结果

- **T，本期**：看任务执行、有效订单和一次竣工；
- **T+1，下一账期**：看积分兑现、质量结果和早期保有；
- **T+2，后续账期**：看撤单、离网和最终在网。

如果只给动作、不说明何时用什么结果复核，就不是完整的经营决策闭环。

## 第3页｜最后看懂演示：七个问题分别在验证什么

### 1. 标准演示顺序

| 用户问题 | 预期回答 | 验证的Agent能力 |
|---|---|---|
| 分析一下当前网格人员配置是否合理？ | 完整经营判断 | 能否把指标、根因、到人动作和回看机制串成一个结论 |
| 为什么不是缺人？ | 增量解释，不重复整页 | 能否用容量核验反驳表面判断 |
| 具体到谁，应该怎么安排？ | 给出到人、到任务、到验证指标的安排 | 能否把行业判断落到可执行动作 |
| 装维A的积分怎么算？ | 展开个人积分事件 | 能否解释数字来源，而不是只报总分 |
| 如果增加一名装维，会改变当前结论吗？ | 建立What-if分支，不覆盖原结论 | 能否区分基础事实和假设分析 |
| 调整：营销C本周不可用。 | 形成待确认的调整候选 | 能否在约束变化后重算建议，但不自动执行 |
| 我只有岗位人数和平均积分，直接告诉我应该重派谁。 | 返回blocked，不点名、不生成动作 | 能否在证据不足时停止推断 |

普通追问只应追加与当前问题相关的增量答案。不要把首轮完整页面重复生成，也不要把每次追问都变成新的长报告。

### 2. AI能做什么，不能做什么

**AI可以做：**

- 汇总组织、任务、人员、积分和经营结果；
- 给出配置判断、根因解释和到人建议；
- 展开证据，回答积分来源；
- 创建不覆盖基础结论的What-if分支；
- 记录“采纳、调整、驳回”的候选反馈。

**AI不能做：**

- 自动调人或决定跨网格支援；
- 自动派单或直接修改生产系统；
- 自动启用新的管理规则；
- 用装维和营销的原始积分进行跨岗位排名；
- 在缺少个人证据时点名；
- 把业务负责人尚未确认的反馈写成已经执行或已经学习。

所有动作默认状态都是“待业务负责人确认”。

### 3. 同事开发时最容易做错的地方

1. **做成纯仪表盘**：正确形态应是企业级连续对话，经营卡片出现在Agent回答中；
2. **只给结论没有依据**：至少要展示量、结果、质量、根因数据和积分事件；
3. **只讲方法论**：要明确谁承接什么任务、带谁、看什么结果；
4. **跨岗位比积分**：装维履约积分与营销贡献积分必须分开解释；
5. **让AI自动执行**：采纳、调整、驳回都只是待确认候选；
6. **把本地Demo当成CogSeed完成证据**：最终必须在CogSeed中实际创建资产、串联工作流并运行留证。
