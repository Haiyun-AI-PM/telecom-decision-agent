# CogSeed 电信行业经营决策 Agent——实训演示 MVP 需求文档

## 0. 客户原始诉求与需求解读

### 0.1 客户原始诉求

> 进入网页，里面有各个 AI 工具；在线操作 AI 工具，就能做出智能体、Skill、RAG 等；最后把这些工具串起来，能跑通一个 AI 应用 Demo；老师能看到 Demo 运行效果，完成评审。

### 0.2 产品解读

客户要验证的不是一个孤立的聊天页面，而是一条完整实训链：

```text
进入实训网页
→ 选择并在线操作 AI 工具
→ 生成 Agent / Skill / RAG 等 AI 资产
→ 在工作流中编排这些资产
→ 运行一个完整 AI 应用 Demo
→ 提交项目
→ 老师查看资产、运行结果和过程证据并评分
```

因此，本项目包含两个相互关联的产品层：

1. **实训工作台层**：展示如何通过多个 AI 工具构建、编排、运行和提交 AI 应用；
2. **业务应用层**：以“电信行业经营决策 Agent”为示范项目，展示最终应用的业务效果。

### 0.3 一句话定位

CogSeed 实训演示 MVP 是一个面向学员与老师的网页式 AI 应用构建工作台：学员通过向导在线生成 Agent、Skill 和 RAG，编排为电信经营决策应用并运行；老师可以复现运行结果、查看构建资产与执行证据并完成评审。

## 1. 本轮目标与非目标

### 1.1 本轮目标

- 让学员在一个网页内完成从创建项目到提交 Demo 的完整流程；
- 至少提供 Agent、Skill、RAG、工作流编排和应用预览五类在线工具；
- 每次工具操作都形成可查看、可编辑、可复用的项目资产；
- 把 Agent、Skill、RAG 和可视化组件串成一条可运行链路；
- 用电信行业经营决策场景证明最终应用能在企业级对话工作台中连续问答并生成结构化可视化结果；
- 老师能够查看项目资产、执行日志、测试结果和最终效果并评分。

### 1.2 本轮非目标

- 不做面向所有行业的通用低代码 AI 开发平台；
- 不做复杂多人协同、企业级权限和真实生产部署；
- 不连接客户真实人员、订单、工单或积分系统；
- 不要求学员编写代码或理解底层模型调用；
- 不自动发布到生产环境；
- 不以模型生成内容的篇幅作为完成标准，以资产和可运行结果为准。

### 1.3 MVP 收敛原则

为保证可演示，首版采用“受约束的场景模板”，而不是无限自由搭建：

- 只有一个默认实训项目：电信行业经营决策 Agent；
- 工具可在线操作，但字段、模板和输出格式预先约束；
- RAG 使用预置脱敏行业材料；
- 工作流节点预置，学员完成配置与连线即可；
- 最终应用使用固定脱敏案例数据；
- 评审标准和测试问题预置。

## 5. 界面需求

### SCR-001｜实训首页

目标：让用户快速进入任务或评审。

组件：

- 课程/实训名称；
- 实训任务卡：名称、目标、预计步骤、状态；
- “开始实训”或“继续项目”；
- 学员项目进度；
- 老师可见“待评审项目”。

### SCR-002｜项目工作台

采用三栏结构：

- 左侧：7个构建步骤和完成状态；
- 中间：当前 AI 工具操作区；
- 右侧：项目资产栏，包括 Agent、Skill、RAG、Workflow、Test、Demo。

顶部固定展示：

- 项目名称；
- 当前保存状态；
- 运行应用；
- 提交评审。

### SCR-003｜Agent 构建器

学员可填写或让 AI 辅助生成：

- Agent 名称；
- 服务对象；
- 核心任务；
- 可回答与不可回答范围；
- 首轮回答结构；
- 多轮意图；
- 人在环上边界；
- 系统提示词。

操作：`AI生成`、`编辑`、`校验`、`保存为Agent资产`。

完成证据：Agent 配置卡＋系统提示词＋校验结果。

### SCR-004｜Skill 构建器

学员配置：

- Skill名称与触发语义；
- 输入字段；
- 行业分析步骤；
- 输出结构；
- 证据不足时的降级规则；
- 禁止动作；
- 验收样例。

操作：`AI生成Skill`、`查看结构`、`规则校验`、`保存`。

完成证据：Skill定义＋输入输出契约＋测试状态。

### SCR-005｜RAG 构建器

MVP 使用预置脱敏材料，学员完成：

- 选择资料；
- 设置知识库名称和用途；
- 自动切片和索引；
- 预览切片；
- 输入问题测试召回；
- 查看引用片段；
- 保存RAG资产。

预置材料范围：

- 省公司、地市公司、区县公司和网格的经营对象与关系；
- 营销贡献账与装维履约账；
- 任务—人员匹配规则；
- T/T+1/T+2验证逻辑；
- 证据和治理边界。

完成证据：知识库概览＋文档数/切片数＋3个召回测试结果。

### SCR-006｜工作流编排

MVP 预置节点，学员完成配置和连线：

```text
用户问题
→ 意图识别 Agent
→ RAG 检索
→ 经营决策 Skill
→ 结构化 DecisionResponse
→ 文本回答
→ 可视化渲染
→ 反馈与会话状态
```

节点必须显示输入、输出、运行状态和错误提示。

操作：`自动编排`、`连线`、`校验工作流`、`保存版本`、`试运行`。

完成证据：工作流图＋版本号＋校验结果。

### SCR-007｜测试与应用预览

分为两个区域：

1. 测试台：运行预置测试问题，显示通过/失败和失败原因；
2. 应用预览：以最终用户视角进入企业级对话工作台，连续提问并查看AI回答中的结构化经营结果。

应用预览最低界面结构：

- 左侧显示最近会话、当前组织与数据范围；
- 顶部显示会话标题、组织路径与数据状态；
- 中部为连续消息流，明确区分用户问题与Agent回答；
- 首轮经营判断以内嵌结构化内容呈现，不跳转到独立仪表盘；
- 回答后提供少量建议追问，底部保留自由输入框；
- 普通追问追加增量消息，不刷新或重复首轮完整结果；
- 完整依据通过唯一入口按需展开；
- 采纳、调整、驳回只更新待确认反馈状态，不触发真实业务执行。

预置必测问题：

- 分析一下当前网格人员配置是否合理？
- 为什么不是缺人？
- 具体到谁，应该怎么安排？
- 装维A的积分怎么算？
- 如果增加一名装维会怎样？
- 调整：营销C本周不可用。
- 只有平均积分，直接告诉我调谁。

### SCR-007A｜员工登录与会话身份

用户Demo首先进入脱敏员工登录页：

- 展示产品名称、适用对象和“脱敏演示环境”说明；
- 使用固定演示员工账号登录，不连接真实员工目录；
- 登录后在顶部和侧栏显示员工姓名、工号、角色与当前组织范围；
- 支持退出登录并返回登录页；
- “新建经营分析”必须可点击，并在最近会话中生成新的本地会话记录；
- 新会话重置追问、反馈和依据展开状态，但不修改固定场景事实。

### SCR-008｜提交与评审

学员提交页显示：

- 资产完成度；
- Agent、Skill、RAG和Workflow版本；
- 必测用例通过率；
- 最后一次成功运行时间；
- Demo运行入口；
- 提交说明。

老师评审页显示：

- 学员提交快照，不随提交后编辑变化；
- 构建资产列表与版本；
- 工作流和执行轨迹；
- 7个标准问题一键运行；
- 文字答案与可视化结果；
- 评分项、评语、退回修改或评审通过。

## 6. 最终业务应用需求

最终应用以“某省—某市—某区县—家庭业务A网格”的脱敏案例运行，当前分析对象为网格，区县作为管理与跨网格协同边界。

组织层级统一采用：

```text
省公司
→ 地市公司
→ 区县公司
→ 网格
```

- 省级：查看全省经营态势、规则和资源配置；
- 地市级：查看地市经营差异和区县协同；
- 区县级：查看下属网格、审批跨网格支援；
- 网格级：分析本单元人员、任务、产品和经营结果。

本次Demo默认角色为“网格负责人”，老师可以切换“区县经营负责人”视角查看支援依据，但MVP不建设完整多级驾驶舱。

### 6.1 首轮回答结构

```text
经营判断
→ 当前网格人员总量先保持，优先重排高价值任务与机会

根因证据
→ 量分质对比
→ 装维任务结构与承接匹配
→ 营销机会承接与转化匹配

本期执行
→ 装维A带装维B完成复杂家庭网络工单
→ 营销A带营销B/营销C复盘高意向客户话术

验证与反馈
→ T / T+1 / T+2
→ 采纳 / 调整 / 驳回
```

### 6.2 企业级对话与可视化形态

最终业务应用采用“企业级对话工作台＋回答内结构化结果”，不是独立驾驶舱或一次性报告页。

对话壳层：

- 最近会话和新建会话入口；
- 当前组织、分析范围和数据状态；
- 用户与Agent组成的连续消息流；
- 建议追问、自由输入和回车发送；
- 当前会话内的反馈与分支状态。

首轮Agent回答内包含：

- 经营判断：是否调人、人员总量、任务重排和支援结论；
- 指标条：装维业务量/结果、营销业务量/结果、质量；
- 根因行：两条有数据支持的根因；
- 行动行：两组主要动作＋10人摘要；
- 验证条：T、T+1、T+2；
- 反馈条：采纳、调整、驳回；
- 唯一深层入口：完整判断依据。

Renderer只读取`DecisionResponse`并渲染，不得再次调用模型补充数字、人员或结论。

### 6.3 多轮问答

必须保持当前案例的人员、根因、动作和会话状态；普通追问以`delta`消息追加到当前消息流，不重复首轮完整结果；What-if创建独立分支，反馈不覆盖基础事实。

多轮最低交互状态：

- `full`：首轮完整判断，渲染全部结构化内容；
- `delta`：为什么、到人、积分等追问，只追加相关解释；
- `blocked`：数据不足时明确缺口，隐藏人员点名和执行动作；
- `branch`：What-if显示为独立假设分支，不覆盖基础结论；
- `feedback`：采纳、调整、驳回形成待确认候选，需业务负责人复核。

### 9.3 硬约束

- Agent负责意图、对话和回答组织；
- RAG只提供检索片段和引用，不直接做最终决策；
- Skill负责行业判断、证据门、行动门和结构化结果；
- Renderer只负责展示，不生成新结论；
- 数据不足时输出 `blocked`，不得猜人、猜根因；
- 所有执行动作都是建议，不触发真实业务写操作。

## 10. 老师评审量表

| 维度 | 权重 | 通过标准 |
|---|---:|---|
| 场景理解 | 15% | 用户、问题、边界和价值清楚 |
| Agent设计 | 15% | 角色、意图、多轮和边界完整 |
| Skill质量 | 20% | 有行业流程、输入输出、降级与治理 |
| RAG质量 | 15% | 资料有效、召回可解释、回答有引用 |
| 工作流编排 | 15% | 资产连接正确，运行轨迹完整 |
| Demo效果 | 15% | 企业级对话形态完整，首轮清楚，多轮只追加增量内容 |
| 安全与反思 | 5% | 不编造、不自动执行，能说明局限 |

评审结果：

- 85—100：优秀；
- 70—84：通过；
- 60—69：退回修改；
- 60以下：未通过。

## 11. 验收 Gate

### G1｜工具可操作

- Agent、Skill、RAG三个工具均可在线操作；
- 每个工具可保存资产并在右侧资产栏看到版本；
- 不是仅展示说明文字或静态截图。

### G2｜链路可运行

- 工作流可以读取三个资产并完成一次运行；
- 运行轨迹显示各节点成功/失败；
- 最终输出文字、结构化数据和可视化结果。

### G3｜业务效果

- 首问3秒内看到是否调人；
- 20秒内看到非显然根因；
- 到人动作与根因一致；
- 经营结果位于连续对话消息流内，不以独立仪表盘替代对话；
- 演示员工能够登录，登录后账号、角色和组织范围清晰可见；
- “新建经营分析”能够创建新的本地会话并重置会话状态；
- 多轮追问不丢失上下文；
- 普通追问不重复首轮完整页面；
- 缺数据场景不会编造。

### G4｜提交评审

- 学员可以提交项目快照；
- 老师可以查看所有核心资产；
- 老师可以直接运行标准问题；
- 老师可以评分、写评语并完成或退回评审。

## 13. 风险与待确认

| ID | 风险/待确认 | 影响 | 建议 |
|---|---|---|---|
| RISK-001 | CogSeed当前是否已有Agent/Skill/RAG构建器 | 影响复用范围 | 先盘点现有组件，缺失部分用受约束表单补齐 |
| RISK-002 | 是否支持自定义工作流和节点轨迹 | 影响工具串联展示 | 首版可用预置节点＋可配置连线 |
| RISK-003 | RAG建库耗时与稳定性 | 影响现场演示 | 预置已索引库，同时保留“重建”演示入口 |
| RISK-004 | 模型结构化输出漂移 | 可视化可能失败 | JSON Schema校验＋一次自动修复＋固定兜底结果 |
| RISK-005 | 老师评审是否要求真实账号体系 | 影响开发量 | MVP先用角色切换模拟，正式版再接账号权限 |
| RISK-006 | 课程是否要求自由选题 | 影响平台通用度 | 本轮只验证电信模板，自由选题放后续版本 |
| RISK-007 | 把本地可交互Demo误认为CogSeed已实现 | 造成完成度误判 | 必须在CogSeed实际运行首轮和多轮，并保存运行与交互证据 |
| RISK-008 | 把固定演示登录误认为真实身份认证 | 造成安全与能力误判 | 页面明确标注脱敏演示，不连接真实员工目录和权限系统 |

## 14. 本版本交付口径

本版本面向“实训链路＋最终AI应用效果”的客户演示验证。通过验收表示：学员能够在线形成Agent、Skill、RAG等资产，完成编排并运行一个电信经营决策Demo；老师能够看到同一提交快照、运行效果和评审证据。它不代表平台已经具备企业级通用开发、真实生产数据接入或生产发布能力。
